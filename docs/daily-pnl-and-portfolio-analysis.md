# 每日盈亏与全账户分析（2026-09-12）

## 使用方式

- 投资总览的「今日涨跌」旁新增「每日盈亏」，点击打开记录抽屉，支持近 30 天、90 天和一年。
- 每次登录或恢复已登录页面时自动刷新行情、汇率和盈亏一次。页面间共享刷新任务；切换币种、曲线或隐私模式不会重复发起登录刷新。失败显示重试入口。
- 「AI 分析全部账户」使用用户默认服务、模型和 Key，可手动覆盖。没有有效可估值资产时不发起付费请求。
- 摘要渲染 Markdown，显示报告输入数据时点与币种，保留上一次成功报告并单独显示新任务状态。隐私模式默认折叠摘要。
- 报告按固定八个章节输出；原始历史报告不会被改写。新规范见 [组合报告 Prompt](portfolio-report-prompt.md)。

## 每日盈亏口径

使用 UTC 日期，与现有资产快照一致。每日保存每个币种的「未实现收益 + 累计已实现盈亏 + 累计分红/利息」，与前一日检查点相减后按当次汇率折算成 CNY、USD。

该口径排除入出金和汇兑变动，不是资产总额变化，也不是投资收益率。今日数值为最近更新时的暂计值。不同市场的报价日期可能不同，获取时间不是交易所报价时间，免费行情仍可能延迟。

首日、漏记日期、价格或成本缺失、行情过期、手动修改本金、删除持仓及更正历史交易时不伪造日盈亏，显示原因并建立新基准。旧快照只有总资产，不能可靠回填历史每日收益。

仅有 CNY 资产但汇率不可用时，可记录 CNY 收益，USD 显示待确认。港币通过 7.8 HKD/USD 近似折算。手填资产只在估值发生更新时反映收益，不会自动获得市场价格。

> **与「今日涨跌」口径不同**：总览的「今日涨跌」= 当日价格变动（昨收 → 现价 × 数量），只反映持仓市价的日内变化；「每日盈亏」= 累计收益的日变化，额外包含已实现盈亏与分红/利息，并排除入出金与汇兑变动。两者是不同口径，数值通常不相等，请勿混用。

## 逐仓位每日盈亏明细

每日盈亏抽屉新增「逐仓位明细」：桌面点击日历日期、列表行点「查看明细」即可查看当天每个平台/账户下各持仓的盈亏。同一股票在不同平台的仓位分别展示，默认按盈亏绝对值降序。

- 明细使用与当日总额一致的「原币累计收益差」口径，不会拿当前行情涨跌幅或市值差代替历史日盈亏；买入、部分卖出、清仓、分红/利息均按累计收益变化正确反映。
- 每个仓位保存历史快照（`details_json`）：平台/账户名称、代码、名称、原币种、累计收益组成、当日原币/CNY/USD 金额、当次汇率与更新时间、有效性状态及原因。名称等为快照值，不依赖当前持仓关联查询。
- 明细金额各自四舍五入到分；逐仓位明细合计与当日总额可能因舍入相差每仓位最多 0.5 分，详情接口通过 `rounding_diff` 显式标注。
- 无法可靠计算时返回空值及原因（如缺价格/成本、新增持仓无前一日基准），不补零、不伪造收益。
- 历史金额沿用该日记录时的汇率，切换展示币种只用已保存的 CNY/USD 金额，不用最新汇率重算过去收益；汇率不可用时显示待确认。
- **历史明细自本功能上线后开始记录**：此前已有每日记录只有汇总（无 `details_json`），查看时会提示「该日期未记录持仓明细」，无法反推逐仓位明细；上线首日总盈亏仍可计算（沿用 per-currency 汇总），但逐仓位明细自次日起才可用。

## 无人访问时的线上更新

`fly.toml` 已设置：

```toml
AUTO_REFRESH_ENABLED = "true"
AUTO_REFRESH_TIME = "07:55"
AUTO_REFRESH_TIMEZONE = "Asia/Shanghai"
AUTO_REFRESH_INTERVAL_HOURS = "24"
AUTO_REFRESH_ON_STARTUP = "true"
min_machines_running = 1
```

计划每天北京时间 07:55（UTC 前一天 23:55）更新所有用户的行情、汇率、资产快照和日盈亏；不要求用户登录。应用重启也会执行一次。保持一个实例运行才能让内置定时任务在无人访问时执行，会产生持续运行费用。当前采用单实例、单 Uvicorn worker；若扩容为多实例，需要改用数据库任务锁或独立调度器。

Fly.io 对最低运行实例的行为见 [官方说明](https://www.fly.io/docs/launch/autostop-autostart/)。服务器停机或外部行情失败时会留下缺失或失败状态，不会伪造补记。运行情况可在总览「自动刷新」查看。

发布命令：

```sh
flyctl auth login
flyctl deploy --app tsfinancialsystem
flyctl status --app tsfinancialsystem
```

发布后应核对运行实例、自动刷新 enabled、计划时区和最新任务结果。若线上已有同名 secret，会覆盖配置文件中的变量，须核对其实际取值。

## 数据与接口

- 新表 `dailypnl`：`user_id + day` 唯一，每日更新同一条；保留累计原币种收益、计算基准、日盈亏、完整性与说明。
- `dailypnl` 新增 `details_json` 字段，保存逐仓位累计收益快照；旧表启动时自动补列（默认 `[]`）。
- `automationrun` 新增可空 `user_id`；旧表启动时自动补列。单用户任务历史按当前用户过滤。
- `GET /api/snapshots/daily-pnl?days=30&currency=CNY`：只返回当前用户的记录、计算口径及 UTC 时区（不含逐仓位明细，避免一次加载全年明细）。
- `GET /api/snapshots/daily-pnl/{day}?currency=CNY`：按日返回逐仓位明细（`total`、`positions`、`has_details`、`rounding_diff` 等），按当前用户隔离。
- `POST /api/automation/run-now?reason=login`：刷新当前用户并记录触发原因。默认 reason 为 manual。
- `GET /api/research/portfolio-summary`：成功报告摘要与 latest_task 分离，as_of 来自输入快照；旧报告未记录时返回空值。
- 备份格式升级至 v2，包含资产快照及每日盈亏（含 `details_json`）；仍兼容旧备份。恢复保留历史金额与明细快照，但因持仓 ID 重建，下一日重新建立计算基准。
